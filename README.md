# نبض · Nabd

منصّة ويب مفتوحة لأي مستشفى، بتربط كل أقسام المستشفى وموظفيه ومرضاه بنظام واحد لحظي.
أي مدير بيقدر يسجّل ويبني مستشفاه على المنصة، وكل مستشفى بيشتغل بمعزل عن الباقي.

> An open, multi-hospital web platform that connects every department, staff member and patient
> in one real-time system. Each hospital is fully isolated by `hospitalId`.

---

## هيكل المستودع · Repository layout

```
nabd/
├── client/            # الواجهة: React + TypeScript (Vite) + Tailwind + React Router
│   └── src/
│       ├── app/       # الراوتر والإعدادات العامة
│       ├── layouts/   # هياكل الصفحات
│       └── pages/     # الصفحات
├── shared/            # @nabd/shared: قواعد التحقق (Zod) والثوابت المشتركة بين الواجهة والسيرفر
├── server/            # الباك إند: Node.js + Express + TypeScript + Prisma
│   └── src/
│       ├── routes/      # تعريف الروابط
│       ├── controllers/ # استقبال الطلب والرد
│       ├── services/    # منطق العمل والوصول للبيانات
│       └── middleware/  # الأخطاء والصلاحيات
├── eslint.config.js   # إعداد ESLint موحّد للمجلدين
├── .prettierrc.json   # إعداد Prettier
└── package.json       # npm workspaces
```

المستودع بيستخدم **npm workspaces**: أمر `npm install` واحد من الجذر بينزّل اعتماديات المجلدات التلاتة.
بالواجهة، الاختصار `@/` بيأشّر على `client/src`.

## البدء · Getting started

```bash
npm install                          # بيولّد Prisma Client كمان
cp server/.env.example server/.env   # وعدّل DATABASE_URL حسب PostgreSQL عندك
npm run db:migrate -w server         # إنشاء الجداول
npm run db:seed -w server            # مستشفى تجريبي ومدير
npm run dev:client   # الواجهة على http://localhost:5173 (صفحة الدخول: /login)
npm run dev:server   # السيرفر على http://localhost:4000 (فحص: /api/health)
```

قبل التشغيل لازم تعمل قاعدتين بيانات فاضيتين بـ PostgreSQL: `nabd` للتطوير و`nabd_test` للتستات (التستات بتبني جداولها لحالها):

```bash
psql -U postgres -c "CREATE DATABASE nabd;"
psql -U postgres -c "CREATE DATABASE nabd_test;"
```

وبملف `server/.env` لازم تحط `JWT_ACCESS_SECRET` عشوائي (32 حرف أو أكتر)، والطريقة مكتوبة بـ `.env.example`.

**الحسابات التجريبية:** بعد `npm run db:seed` في حساب لكل دور، وكلمة السر لكلهن `Admin@12345` (بتتغيّر من `SEED_PASSWORD`):
`admin@nabd.demo`، `doctor@nabd.demo`، `nurse@nabd.demo`، `pharmacist@nabd.demo`، `lab@nabd.demo`، `radiology@nabd.demo`، `cleaner@nabd.demo`، `reception@nabd.demo`، `accountant@nabd.demo`، `patient@nabd.demo`. وبوقت التطوير صفحة الدخول فيها أزرار للدخول بأي واحد منهن.

وفي كمان فرق المستشفى (`server/prisma/seedPhaseTwo.ts`): كل قسم سريري فيه 3 أطباء (بحالات مختلفة: متفرّغ، مشغول، بإجازة) و3 ممرضين، وكل قسم فيه عاملين نظافة، وفني أشعة لكل نوع (`rad.ct@`، `rad.mri@`، `rad.echo@`، `rad.endoscopy@`، `rad.panoramic@`، و`radiology@` للأشعة X). الحسابات: `dr.<قسم>.<رقم>` و`rn.<قسم>.<رقم>` و`cl.<قسم>.<رقم>` `@nabd.demo`، والأقسام: `er`، `or`، `internal`، `neuro`، `ortho`، `cardio`، `plastic`، `eye`، `gyn`، `lab`، `radiology`، `pharmacy` (مثلاً `rn.or.1@nabd.demo` ممرض العمليات، و`dr.ortho.1@nabd.demo` الجرّاحة اللي عم تعمل عملية). وأول مرة بيتعبّى المستشفى: إسعاف فيه مريض بكل مستوى خطورة (والمستعجلين متأخرين)، استدعاء ناطر رد `doctor@`، غرفة عمليات قيد العملية، وحدة محجوزة، ووحدة بانتظار التعقيم، وطلب تنظيف. إذا المستشفى التجريبي فيه نشاط من قبل، ما بيضيف فوقه. وأسبوع شغل (`server/prisma/seedPhaseThree.ts`): دوام لكل طبيب (صبحي من السبت للخميس أو مسائي أربع أيام)، سبع مرضى على أسرّة بأقسام مختلفة مع تقرير قبول ووصفة ناطرة الصيدلية وتحاليل (بعضها بنتيجة) وطلبات أشعة ناطرة، ومواعيد محجوزة لمرضى العيادات بالأيام الجاية، وكم مادة بالصيدلية على حافة حدها الأدنى. بيمرق من خدمات التطبيق نفسها وبينضاف مرة وحدة. والمخزون (`server/prisma/inventoryCatalog.ts`): 164 مادة للصيدلية (أدوية بأسمائها العلمية وعياراتها، سيرومات، شاش وضمادات، سرنغات وكانيولات، قفازات وتعقيم، قثاطر وخيوط)، 41 للمخبر، و20 للأشعة، وكم وحدة منهن ناقصة عن قصد لتنبيهات النقص.

السيرفر بيفحص الاتصال بقاعدة البيانات أول ما يشتغل، وإذا ما قدر يوصل بيوقف برسالة واضحة.

- بالواجهة كل الطلبات بتمرق من `api` بـ `client/src/lib/api.ts`: بيضيف التوكن واللغة، وبيجدد الجلسة ويعيد الطلب لحاله، وبيطلّع توست للأخطاء (إلا إذا بعتنا `skipErrorToast`). عنوان السيرفر بـ `VITE_API_URL` (شوف `client/.env.example`).
- بيانات السيرفر بالواجهة بتنجاب بـ TanStack Query (`useQuery` فوق `api`)، والمستخدم الحالي من `useSessionStore`. الجلسة بترجع لحالها بعد إعادة التحميل من كوكي التجديد، ولغة المستخدم ووضع العرض بينحفظوا بحسابه.

## الاتصال اللحظي · Realtime

Socket.io شغّال على نفس منفذ الـ API. الاتصال بياخد نفس توكن الدخول (`auth: { token }`)، والسيرفر بيرفض أي توكن غلط أو منتهي أو حساب موقوف، وبيسكّر الاتصال لما يخلص التوكن (الواجهة بتعيد الاتصال بتوكن جديد).

كل اتصال بينضم لغرف، والإشعار بينبعت لغرفة، فما بيوصل شي لمستشفى تاني:

| الغرفة                      | مين فيها                                               |
| --------------------------- | ------------------------------------------------------ |
| `hospital:<hospitalId>`     | كل مستخدمي المستشفى                                    |
| `user:<userId>`             | المستخدم نفسه (كل أجهزته)                              |
| `role:<hospitalId>:<ROLE>`  | كل أصحاب هالدور بالمستشفى، متل عمال التعقيم أو الأطباء |
| `department:<departmentId>` | موظفين القسم، وعمال النظافة اللي بيغطّوه               |

بالسيرفر: `emitTo(rooms.department(id), 'event', payload)` من `server/src/realtime/realtime.ts`. ولما المدير بيغيّر دور موظف أو قسمه أو بيوقفه، غرفه بتتحدث فوراً (`syncUserRooms`).

**الإشعارات:** أي ميزة بتبعت إشعار عن طريق `sendNotification(db, hospitalId, { to, type, data, link })` من `server/src/services/notification.service.ts`. المستلمين (`to`) يا أشخاص محددين `{ userIds }`، يا دور كامل `{ role }`، يا دور بقسم `{ role, departmentId }`. الإشعار بينحفظ لكل مستلم، وبيوصله لحظياً بحدث `notification`. أنواع الإشعارات واللي منها عاجل بـ `shared/src/notifications.ts`، والنص بيكتبه كل مستخدم بلغته من النوع والتفاصيل.

**بالواجهة:** الاتصال بيفتح لحاله لما حدا يسجّل دخول وبيتسكّر لما يطلع (`client/src/hooks/useRealtime.ts`). كل إشعار بيطلع كتوست بلغة المستخدم، والعاجل بيرن. ولما يتغيّر شي بالسيرفر، `emitRefresh(room, [['operating-rooms']])` بيخلّي الشاشات المفتوحة تجيب البيانات من جديد. ولتجرّب الإشعارات بوضع التطوير، في زرّين بـ `/dev/ui` (المسار `POST /api/dev/notify` ما بينضاف بالإنتاج).

## الملف الطبي · Medical file

كل مريض إله ملف طبي واحد بكل مستشفى (`MedicalRecord`)، بينعمل معه لما يتسجّل، وفيه الطبيب المعالج والحساسيات والأمراض المزمنة. تقارير الأطباء (`DoctorReport`) والوصفات (`Prescription`) مربوطين بالملف، وكل وصفة فيها دواء أو أكتر (`PrescriptionItem`)، وحالتها: بانتظار الصرف، أو انصرفت، أو ملغاة.

التقارير والوصفات جزء من تاريخ المريض: إذا انحذف حساب طبيب بتضل محفوظة، ومعها اسمه. وإذا انحذف المريض بينحذف ملفه كله.

## الإسعاف · Emergency room

كل زيارة إسعافية سجل بـ `TriageAssessment`: بينعمل بالتسجيل السريع (حتى لمريض مجهول)، وبعدين بتتعبّى العلامات الحيوية (النبض، الضغط، التنفس، الأكسجة، الحرارة، الوعي بمقياس AVPU، الألم من 0 لـ10). فيه المستوى المقترح (1 لـ5) والنهائي مع سبب التعديل، وحالة الزيارة: بالانتظار، أو قيد العلاج، أو تحوّل لقسم، أو تخرّج. قاعدة البيانات نفسها بترفض القيم المستحيلة (متل مستوى 6 أو أكسجة 120).

**اقتراح مستوى الخطورة (ESI):** `suggestEsiLevel` بـ `shared/src/triage.ts`، وهي نفس القواعد بالفورم (اقتراح لحظي) وبالسيرفر (هو اللي بيحفظ المستوى):

1. ما عم يتنفس أو ما بيستجيب → **1**.
2. وعي مش طبيعي (بيستجيب للصوت أو للألم بس)، أو أي علامة حيوية برّا الطبيعي، أو ألم فوق 7 → **2**.
3. غير هيك حسب الفحوصات المتوقعة: فحصين أو أكتر → **3**، فحص واحد → **4**، ولا فحص → **5**.

الأرقام اللي ما انقاست ما بتنحسب، والمستوى المقترح بيصير هو المعتمد إلا إذا الممرض عدّله بسبب.

استدعاء الطبيب (`DoctorCall`) بيسجّل مين انطلب ومين طلبه، وجوابه (قبول أو اعتذار مع السبب).

## غرف العمليات والتنظيف · Operating rooms and cleaning

- **حجوزات العمليات** (`OperationBooking`): الغرفة والجرّاح والمريض والعملية ووقت البداية والنهاية (قاعدة البيانات بترفض حجز بيخلص قبل ما يبلّش). الحجز الإسعافي ممكن يكون بلا غرفة لحد ما تفضى أول وحدة.
- **سجل حالة الغرفة** (`OperatingRoomStatusChange`): كل تغيير، من شو لشو، ومين ووقتيش. أي تغيير بيمرق من `changeRoomStatus` بـ `server/src/services/roomStatus.service.ts`، وبينقرأ من `GET /api/operating-rooms/:id/history`.
- **آلة حالات الغرفة** (`shared/src/orStateMachine.ts`): فارغة ← محجوزة (ممرض إسعاف أو طبيب، من الحجز بس) ← قيد التحضير ← قيد العملية ← بانتظار التعقيم (ممرض العمليات) ← قيد التعقيم ← فارغة (عامل التعقيم المكلّف بقسم العمليات). المدير بيطلّع الغرفة الفارغة من الخدمة وبيرجّعها. كل خطوة بتمرق من `POST /api/operating-rooms/:id/transition`، و`GET /api/operating-rooms/me` بيقول شو صفتي (`ER_NURSE`، `OR_NURSE`، `STERILIZER`…). خطوات ممرض العمليات بتحمل الحجز معها: بدء التحضير بياخد أول حجز ناطر (أو اللي اختاره) لـ "قيد التنفيذ"، بدء العملية بيسجّل وقتها، والإنهاء بيكمّل الحجز.
- **الحجز المجدول** (`server/src/services/booking.service.ts`): الطبيب بيختار مريض من مرضاه وغرفة ووقت ومدة من صفحة حجوزات العمليات. السيرفر بيقفل سطر الغرفة (`FOR UPDATE`) وهو عم يفحص التعارض، والواجهة بتنبّه عالتعارض قبل الحفظ.
- **طلب التعقيم** (`server/src/services/cleaning.service.ts`): لما ممرض العمليات ينهي العملية، الغرفة بتصير بانتظار التعقيم، وبينحفظ طلب تعقيم لقسم العمليات (واحد مفتوح بس لكل غرفة)، وبيوصل إشعار عاجل مع صوت لكل عامل نظافة مكلّف بقسم العمليات.
- **طلبات التنظيف والتعقيم** (`CleaningRequest`): لعمال النظافة بقسم معيّن، لغرفة عمليات أو سرير أو مكان، مع مين طلب ومين اشتغل ووقت البداية والنهاية.
- **المخزون** (`InventoryItem`): مخزون الصيدلية والمخبر والأشعة (`DRUG` و`LAB` و`RADIOLOGY`)، لكل مادة وحدة وكمية وحد أدنى. القاعدة نفسها بترفض كمية سالبة.
- **حركات المخزون** (`StockMovement`): كل تغيير بالكمية، قديش ولشو وشو بقي ومين عمله. الكمية بتتغير بس من `moveStock` بـ `server/src/services/inventory.service.ts`: بتقفل سطر المادة، بترفض النزول تحت الصفر (`OUT_OF_STOCK`)، وبتقول إذا المادة هلق وصلت للحد الأدنى.
- **تنبيه النقص** (`announceLowStock` بنفس الملف): لما مادة توصل لحدها الأدنى (بصرف أو جرد، أو انضافت ناقصة، أو ارتفع حدها الأدنى)، بيوصل إشعار `LOW_STOCK` لكل اللي بيهتموا بهالمخزون (الصيادلة، فنيي المخبر، أو فنيي الأشعة) غير اللي عمل الحركة، لأنه شايف التنبيه بشاشته. والإشعار بياخد عصفحة المخزون. الصرف من الوصفات (3.10) بيمرق من نفس الدالة.
- **التحاليل** (`LabTest`): تحليل طلبه طبيب لمريض، برمز من `LAB_TEST_GROUPS` بـ `shared/src/lab.ts` (كل لغة بتسمّيه)، أولويته وحالته (بانتظار المخبر، عم ينعمل، جاهز، منسحب)، واسم الطبيب محفوظ. وفيه مكان للنتيجة (نص وملف) للمهمة 3.5.
- **صور الأشعة** (`RadiologyImage`): طلب طبيب لنوع معيّن (كل فني أشعة إلو نوع) ولمنطقة من الجسم، مع السؤال السريري والأولوية وحالة الطلب، واسم الطبيب محفوظ. فيه مكان للتقرير وملفات الصور (3.8). كل طلب بيوصل لفنيي نوعه بس: كل فني أشعة بينضم لغرفة اتصال مباشر خاصة بنوعه (`rooms.modality`). وبملف المريض في عارض صور (`client/src/components/patients/ImagingViewer.tsx`): تكبير بالأزرار والعجلة والضغط مرتين، سحب الصورة المكبّرة، ملء الشاشة، تنقّل بالأسهم والمصغّرات. الصور بتنجاب بتوكن الجلسة كـ blob (ما في رابط عام) وبتنمسح من الذاكرة لما يتسكّر.

## قواعد الكود · Conventions

- كل الكود TypeScript بوضع `strict`.
- كل قاعدة تحقق (فورم أو body طلب) بتنكتب مرة وحدة بـ `shared/src/schemas` بـ Zod، والواجهة والسيرفر بيستعملوا نفس الـ schema. رسائل الأخطاء فيها مفاتيح ترجمة (`validation.*`)، وكل مفتاح جديد لازم ينضاف لـ `VALIDATION_KEYS` وللترجمات.
- ما في نص مكتوب مباشرة بالواجهة: كل النصوص بـ `client/src/i18n/locales/ar.ts` و`en.ts`. الملفين لازم يكون فيهن نفس المفاتيح، وإذا نقص مفتاح من وحدة منهن البناء بيفشل.
- الاتجاه بيتقلب لحاله مع اللغة: استعمل `ms-`/`me-`/`ps-`/`pe-`/`start-`/`end-` بدل `ml-`/`mr-`/`left-`/`right-`، والأيقونات يلي إلها اتجاه (أسهم) بتاخد `rtl:-scale-x-100`.
- كل جدول (ما عدا `Hospital`) فيه `hospitalId`، وكل استعلام بيتقيّد فيه: الروابط يلي بدها دخول بتمرق من `authenticate` (و`requireRole` للأدوار)، وبتستعلم عن طريق `req.db` بس، وهي نسخة Prisma بتضيف مستشفى المستخدم لحالها لكل قراءة وكتابة. الـ `prisma` العادي ممنوع بالروابط المحمية.
- مكوّنات الواجهة الأساسية بـ `client/src/components/ui` (زر، حقل، قائمة، جدول، كرت، نافذة، شارة). استعملها بدل ما تكتب عناصر جديدة، وشوفها كلها على `/dev/ui` وقت التطوير.
- الحركة: كل انتقال CSS بياخد منحنى `--ease-calm` تلقائياً، وبـ Framer Motion استعمل `calm` و`calmSpring` و`enter()` من `client/src/lib/motion.ts`، مشان تضل كل الحركات بنفس الإحساس الهادي. وإعداد "تقليل الحركة" بالجهاز بيوقّفها كلها.
- الأصوات: الرسائل منطلعها بـ `notify` من `client/src/lib/notify.ts` (توست مع صوته)، والأصوات لحالها بـ `playSound` من `client/src/lib/sound.ts`. الأصوات مولّدة بالكود (Web Audio) وبتحترم إعدادات المستخدم.
- الألوان من متغيرات الهوية بـ `client/src/index.css` بس (`bg-surface`، `text-muted`، `bg-danger`...)، وما في كود hex بالمكوّنات، مشان الوضع الداكن يشتغل لحاله.
- كل صفحة لازم تشتغل من عرض 320px (موبايل) لحد الشاشات الكبيرة، بلا تمرير أفقي. منبلّش بتصميم الموبايل وبعدين منكبّر بـ `sm:` و`md:` و`lg:`.
- المحرّر بينسّق تلقائياً عند الحفظ، وPrettier بيرتّب كلاسات Tailwind (إعدادات `.vscode` مرفقة).
